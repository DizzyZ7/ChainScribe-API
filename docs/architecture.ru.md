# Архитектурные решения

[English version](architecture.md)

## Критерий завершенности

Критический пользовательский сценарий включает регистрацию, создание и изменение статьи после аутентификации, создание комментария после аутентификации, удаление ресурсов только владельцем и выход из системы, который немедленно делает текущий токен недействительным.

Работа считается завершенной только при наличии исполняемых тестов, CI на PostgreSQL и контейнерного smoke-сценария.

## ADR-001: непрозрачный токен и JWT остаются раздельными механизмами

Требования проекта явно предусматривают случайный токен длиной 256 символов и дополнительную поддержку `django-ninja-jwt`. JWT является подписанным структурированным набором данных и не может корректно заменять случайный непрозрачный секрет.

Поэтому ChainScribe принимает две однозначно различимые схемы авторизации:

- `Token` — случайный 256-символьный секрет, который хранится только в виде хеша;
- `Bearer` — короткоживущий JWT access-токен.

Выход из системы отзывает предъявленный непрозрачный токен. Для завершения JWT-сессии refresh-токен добавляется в blacklist через отдельный endpoint.

## ADR-002: авторство никогда не принимается из входных данных

Схемы статей и комментариев запрещают дополнительные поля. Автором ресурса транзакционно назначается аутентифицированный пользователь.

При изменении объекта сервис загружает его с блокировкой строки и повторно проверяет владельца. Это защищает как от прямого IDOR, так и от гонки между проверкой права доступа и фактическим изменением.

## ADR-003: черновики фильтруются до применения пользовательских фильтров

Селектор сначала формирует границу видимости для текущего пользователя и только после этого применяет фильтры по категории, статусу и автору.

Анонимный пользователь не может определить существование приватного черновика по количеству результатов или значениям фильтров.

## ADR-004: операционные журналы и события безопасности разделены

Структурированные логи в stdout предназначены для диагностики и агрегации. События аудита в базе данных предназначены для фиксации того, кто, что и с каким результатом сделал. В них намеренно не сохраняются содержимое публикаций и учетные данные.

Модель аудита и Django Admin запрещают изменение и удаление записей. Для сред с повышенными требованиями события дополнительно следует экспортировать во внешнее хранилище с однократной записью.

## ADR-005: PostgreSQL является основной и авторитетной СУБД

PostgreSQL предоставляет протестированные ограничения целостности, UUID-индексы, блокировки строк и транзакции.

Явный переключатель SQLite существует только для ограниченной локальной диагностики разработчиком. CI и production его не используют.

## Жизненный цикл данных

- Пользователи обычно деактивируются, а не удаляются.
- Удаление пользователя запрещено, пока существуют созданные им материалы.
- Удаление категории запрещено, пока на нее ссылаются публикации.
- При удалении статьи каскадно удаляются ее комментарии.
- Выход по непрозрачному токену записывает `revoked_at`, не удаляя свидетельство существования токена.
- Просроченные записи blacklist JWT очищаются командой `flushexpiredtokens`.

## Границы доверия

Обратный прокси завершает публичное TLS-соединение и применяет базовые правила WAF и ограничения частоты запросов. Gunicorn получает уже ограниченные HTTP-запросы.

Django проверяет origin, структуру входных данных, учетные данные и владение ресурсами. Redis считается доверенным только для временного состояния rate limiting. PostgreSQL является системой учета и источником истины.

Секреты передаются приложению только через окружение процесса или менеджер секретов платформы.
